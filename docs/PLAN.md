## Maintenance & polish

Work no milestone asked for: refactors of already-shipped milestones, and visual polish.
Tracked here so it stops appearing in the git log as if it were milestone progress.

### Found by 009's two-theme sweep, deliberately not absorbed by it
009 measured every shipped surface in both themes, which surfaced pre-existing gaps it did not cause.
They are listed here rather than folded in, because a task that merely *finds* a gap should not be the
one blocked by it. Each is non-blocking; none is a 009 regression.

- [ ] **Dead `disabled:` utilities on the task-form fields.** `components/TaskForm.tsx:169,189,251` carry
      `disabled:` styling but are never handed a `disabled` attribute — only submit and cancel are, via
      `submitting`, and line 61 says the fields are deliberately left enabled ("a disabled input blurs
      itself, which would undo the add"). Same class of defect as 009's R-1b (`dark:` utilities that had
      never rendered). Two instances in one week suggests dead conditional styling is a pattern worth a
      repo-wide grep, not a one-off fix.
- [ ] **320 px header density.** The theme control wraps the header 40→80 px, pushing the gauge top from
      312 px to 352 px. Accepted deliberately by owner ruling; 40 px matters on a 568 px-tall viewport, so
      a compact treatment is worth a look — but not icon-only, which would cost the text labels that make a
      three-state control legible.
- [ ] **Drag-active row ring at 2.47:1 in light.** `components/TaskRow.tsx:116`. Exempted under criterion
      42 because the dnd transform and `opacity-60` both carry the drag state; recorded in DECISIONS with
      provenance (it predates 007 *and* 009). Fixing it needs a dedicated `--drag-ring` token, since `--ring`
      is pinned by criterion 27 and colours every focus ring in the app.
- [ ] **`widgets/HeaderNav.tsx` is a `<div>`, not a `<header>` landmark**, and sits inside `<main>` — so an
      app-level control now lives in the main landmark. Pre-existing shape; 009 made it more visible by
      putting the theme control there.
- [ ] **A dragging row's own title text drops below 4.5:1** for the duration of the drag, via `opacity-60`.
      Transient and pre-existing; no criterion covers it.
- [ ] **Drop the unused `lucide-react` dependency.** `package.json` carries `lucide-react@^1.52.0` and it is
      imported nowhere — all four icon usages are `react-icons`, ratified as the project's library on
      2026-10-26. Deferred out of 008 by pm: that task's criterion 18 pins `package.json` to an empty diff,
      which is the cheapest dependency guard available, and removal means lockfile churn plus its own check
      that a future `shadcn add` does not reinstall it.

- [ ] **`/settings` selected option is thin under forced colours** (review R-1). `components/SettingsPanel.tsx:52-55`
      carries checked state with `peer-checked:border-primary` plus an inset `box-shadow`; forced-colors
      forces every border to one system colour and `box-shadow` to `none` (CSS Color Adjust 1 §3.2), and the
      radio is `peer sr-only`, so **font weight is the whole indicator** on the one screen whose job is
      choosing. Not a WCAG failure (weight is a non-colour cue) and no criterion requires it. Cheapest fix:
      `forced-colors:not-sr-only` on the input, restoring the native dot. **The comment at
      `SettingsPanel.tsx:22-25` claiming it "holds in greyscale and forced colours" is wrong and should be
      corrected with the fix** — greyscale holds, forced colours does not.
- [ ] **Glyph waterline calibration assumes the webfont painted** (review R-3). The stop
      `14 + 0.7·level + 0.4·max(0, level-90)` is calibrated to Space Grotesk's ink box at 60-96 px; if the
      face 404s or during the `font-display` fallback window, the stop no longer lands on the ink — the same
      class as the F5 muted-cap bug. Nothing asserts it.
- [ ] **No level cue at all below the `@supports (background-clip: text)` boundary** (review R-4). Older
      Safari gets legible digits but, in glyph mode, no level indicator of any kind rather than a fallback to
      the vessel. Criterion 31 is satisfied; narrow browser set; recorded rather than worked.
- [ ] **Light dialogs do not separate from the scrimmed page at 3:1** (task 010 QA pass 2, owner deferred
      it out of 010 on 2026-10-27). `--dialog-edge` is `var(--border)` (`#d6d3d1`) in light and measures
      **2.00:1** against the scrimmed page, **1.43:1** against the dialog fill. The fill itself is only
      **2.87:1** against the scrim, so moving the edge token alone does not fix the separation — 4 % short
      on the fill is the part that makes this more than a token re-point. Dark clears it (edge 3.92-4.01:1,
      measured under a background image). Pre-existing and unchanged from HEAD, so 010 neither caused it
      nor carried a criterion for it. `e2e/uploaded-background-dialog-edge.spec.ts` records the light case
      as a `test.fail`, which goes green the moment this is fixed — **flip it to a real assertion then, or
      the fix lands with a test that now fails for passing.** Deferred because the palette has to move
      first and be measured once (see CLAUDE.md "Measurement ordering"); re-opening a measured task to do
      it would have cost a second sweep.
- [ ] **`/settings` announces its idle state on arrival** (task 010 review R-1).
      `components/BackgroundControl.tsx:129-131` renders `notice?.text ?? stateText` inside `role="status"`,
      and `stateText` flips from `""` to "No background image." as soon as `hasHydrated` turns true — so a
      screen-reader user hears a state read-out every time they land on `/settings`, having done nothing.
      Fix: idle text in a plain element, live region empty until an action produces a notice.
- [ ] **One storage-failure message covers two unrelated failures** (task 010 review R-3).
      `components/BackgroundControl.tsx:19-20` says "Close any other Pomotato tab and try again." That is
      right for `DatabaseBlockedError` and wrong for `DatabaseUnavailableError` (private browsing, storage
      disabled), where it tells the user to close a tab that does not exist. Both classes are exported from
      `lib/db/index.ts`, so this is one `instanceof` and a second string.
- [ ] **The background layer has no `onError`** (task 010 review R-5). `components/BackgroundLayer.tsx:37`.
      A blob that passes the hook's decode probe but fails in the layer leaves `data-background="pending"`
      forever and holds the object URL until the id changes or `/` unmounts. Nothing paints, so no contrast
      floor is at risk — but the state machine has no terminal failure state for an observer to read, and
      `data-background` is the protocol the e2e suite measures against.
- [ ] **Focus after Remove lands on a visually hidden control** (task 010 review R-2).
      `components/BackgroundControl.tsx:95` focuses the `sr-only` input. Keyboard users do get a ring
      (Chromium keeps `:focus-visible` through a programmatic focus following a keyboard activation, QA
      observed it); after a pointer activation, focus sits somewhere with no visible indicator. Acceptable
      as shipped. If revisited, move focus to the label's span with `tabindex="-1"`.
- [ ] **The newest Dexie version block is still pinned to a moving constant** (task 010 review, ruling D).
      `lib/db/database.ts:56` declares the current version as `.version(CURRENT_SCHEMA_VERSION)`. Task 010
      had to hand-literalize the *previous* block to `.version(2)` for exactly this reason — a historical
      block pinned to the constant silently renumbers itself on the next bump, which is latent data loss.
      The next schema change repeats that manual step. Retire the pattern: literalize `.version(3)` now, or
      add a one-line guard that the highest declared literal equals `CURRENT_SCHEMA_VERSION`.
- [ ] **Small cleanups from task 010's review, none blocking.** R-4: the picked file is read and decoded
      twice (`BackgroundControl.tsx:30` then `background-repository.ts:45`) — deliberate ordering, harmless
      at the 5 MiB cap, worth passing the buffer through if the cap ever rises. R-7:
      `lib/db/background-repository.ts:13` imports `isBackgroundId` from `../preferences/schema`, so the
      data layer depends on the preference module; no cycle today, but the row-id shape belongs to
      `lib/db/`. R-8: `lib/db/background-migration.test.ts:53` uses `mode: "focus" as never` where
      `SESSION_MODES` is exported, and `:64` wraps an assertion in `if (stored.ok)` — one of the four
      vacuity shapes DECISIONS 2026-10-09 names, though it cannot pass vacuously here. R-9:
      `e2e/settings-gauge-style.spec.ts:300,350` no longer asserts how many fieldsets `/settings` has, now
      that legend lookups are scoped by text; one `toHaveCount(2)` restores it.

**Constraint to keep visible, not a task:** dark `--popover` cannot be lifted for elevation. Potato
(`#8a5a2b`) and slate clear it by 3.04:1 and 3.05:1 — 1.3 % of headroom — and the eight task swatches are

caught, but it would break criterion 19. Relevant to 008 and to any future elevation work.
